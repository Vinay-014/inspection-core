System Architecture & Engineering Review
InspectionCore is built to production engineering standards for home inspection companies migrating off Spectora. The system is architected around data preservation, hierarchy integrity, transactional consistency, and non-destructive auditing.
1. Architectural Scalability & Enterprise Hardening
The application runs on an Express + Vite full-stack foundation connected to a persistent PostgreSQL (Supabase) database, engineered with the following resilience mechanisms:
Chunked Batch Ingestion (
 DB Roundtrips): The importer pre-computes UUIDs and persists templates, sections, items, and comments in chunked multi-row inserts (INSERT INTO ... VALUES (...)). This prevents connection starvation, parameter overflow, and the classic 
 latency cliff on large inspection templates (500+ items).
Transient Network Retry & Backoff: Database queries are guarded with exponential backoff and jitter against transient disconnects (ECONNRESET, ETIMEDOUT, 08006, 57P01), ensuring stability across cloud network boundaries.
Atomic Duplication Isolation: The deep-copy engine duplicates templates within a single atomic database transaction (BEGIN...COMMIT), guaranteeing that the duplicated template and its entire tree (sections, items, comments, issues) have completely independent primary and foreign keys. Modifying a duplicate never mutates the source.
Strict Boundary & Route Guarding: Route parameters undergo UUID regex validation prior to query execution. Global error interceptors handle malformed JSON and 30MB payload boundaries.
Graceful Lifecycle Management: Express listens on 0.0.0.0:3000 with clean SIGTERM/SIGINT handlers that drain pending HTTP requests and shut down PostgreSQL connection pools cleanly.
2. Core Requirements & Baseline Capabilities
Baseline Requirement	Production Implementation
1. Import	Multipart streaming upload supporting .xlsx and .xls files. Preserves 100% of text, hierarchy, and 1-indexed ordering. Dynamic header detection accommodates leading metadata and variable row offsets. Non-standard content is surfaced in an audit drawer rather than dropped or rewritten.
2. Edit	Real-time hierarchical editor allowing instant editing and persistence of Section names, Item names, and Comment HTML text. Includes split-pane rendered preview, syntax-highlighted code editor, and change diff trackers.
3. Copy	Fast deep-copy duplication endpoint creating entirely independent relational graphs. Verified by automated tests showing zero mutation leakage.
4. Store	Fully persistent PostgreSQL backend (Supabase). Changes survive page reloads, browser cache purges, container restarts, and multiple sessions.
5. Data Model	Normalized relational schema: templates 
 sections 
 items 
 comments, plus import_issues. Individual comments store rich HTML; templates are never stored as opaque blobs.
3. Formatting, Links, and Rich Content Handling
Preserved Rich Formatting: Supported HTML tags (<p>, <strong>, <b>, <em>, <i>, <u>, <s>, <ul>, <ol>, <li>, <h1>-<h6>, <table>, <blockquote>, <code>) are retained verbatim.
Sanitization & Security: Inline attributes are normalized; active scripts, <style>, <iframe>, and event handlers (onload, onerror) are stripped using DOMPurify to eliminate XSS risks.
Unsupported vs. Missing Content:
Unsupported: Valid content that the parser deliberately neutralizes (e.g., <script> tags, inline <style> sheets) generates an ImportIssue with UNSUPPORTED_HTML status so inspectors can review it.
Missing: Missing section headers or unmapped columns trigger INVALID_STRUCTURE errors that halt import with clear diagnostic guidance rather than producing corrupt records.
4. High-Impact Customer Improvement: Pre-Commit Trust Engine
Inspectors have tuned these templates over four years; their biggest anxiety is silent corruption or lost observations. To address this, the following capability was prioritized:
Dry-Run Audit & Cryptographic Preservation Fingerprinting:
Uploading a file triggers a non-destructive dry-run analysis.

Generates a Preservation Score (e.g., 100.0%) and itemizes warnings (e.g., stripped tags, long observation text) in a pre-commit audit modal before any database write occurs.
